# 対応範囲と限界（Scope 1 / 2 / 3）

本書は、**現在の実装から読み取れる**算定の対応範囲・前提・限界をまとめたものである。

> **本書は制度適合性の判定でも、第三者保証の取得を示すものでもない。**
> 温対法（SHK 制度）・SSBJ / ISSB・GHG プロトコル等への適合可否、および
> 算定結果の妥当性は、利用者・その監査人・保証機関の判断による。
> 本ツールは「公表された排出係数を使って活動量に乗じ、集計・可視化する」までを行う。
> 検証済みと言えるのは、下記「7. 検証されている範囲」に挙げた自動テストが通っている範囲だけである。

算定式・係数選択の詳細は [`calculation-logic.md`](calculation-logic.md)、
Scope 3 積上げの詳細は [`idea-scope3-spec.md`](idea-scope3-spec.md) を参照。

凡例: ✅ 対応 ／ ⚠️ 限定的（前提つき・要カスタム係数） ／ ❌ 未対応

## 2. 対象ガス — 実質的に CO2 のみ

- 同梱の公式係数はすべて **CO2 のみを対象とした係数**（単位表記も `t-CO2/kWh`, `tCO2/t` 等）。
  燃料係数は「算定省令 別表第1 × 別表2 ×（44/12）」＝ 燃料燃焼由来の CO2 である
  （`scripts/official-factors/data/fuels.tsv` 冒頭）。
- 単位換算（`src/features/calculation/engine/units.ts`）は `t-CO2` 系の分子を
  **t-CO2e へ 1:1 で読み替える**。すなわち「CO2 の量を CO2e として計上する」実装であり、
  他ガスの寄与はゼロとして扱われる。
- CH4 / N2O / HFC / PFC / SF6 / NF3 を入力・算定・按分する仕組みは**コードベースに存在しない**
  （該当する型・カラム・係数のいずれも無い）。
- したがって画面・レポートの `t-CO2e` 表記は、**CO2 以外のガスを含まない値**である。
  非 CO2 ガスを含めたい場合は、利用者が外部で算定した値をカスタム係数か
  Scope 3 直接入力として持ち込む必要がある。

**GWP について**: GWP モデルを選ぶ余地があるのは Scope 3 の IDEA 取込のみ
（既定 IPCC 2021 (AR6) GWP 100a without LULUCF、取込時に選択・記録し出典欄に表示）。
Scope 1 / 2 側は CO2 のみのため GWP の選択は生じない。

## 3. Scope 1 の対応範囲

- 対象は **エネルギー起源 CO2**（燃料の燃焼、都市ガス）に限られる。
- 手動入力で選べるカテゴリは 7 種（電気・ガス・熱・廃棄物・燃料・出張・通勤。
  `src/features/data-input/types.ts` の `MANUAL_ACTIVITY_CATEGORIES`）。活動量の入力は手動入力のみで、
  ファイル取込は無い。
- 「燃料」は `energyType = 'fuel'` の 1 カテゴリで、同梱の 35 種（ガソリン・灯油・LNG・炭種 等）を
  同じ優先度の候補として持つ。自動では決められない（`FACTOR_AMBIGUOUS`）ため、
  **入力時に候補から燃料種を選ぶ**。選ばずに保存したレコードは未算定として残る。
  `fuel_gasoline` 等の細目 `energyType` は既存レコードの履歴表示・係数マスタの種別表示用に残っている。
- `vehicle`（km）・`water`（m3）・`logistics`（t-km）・`purchased_goods_services`（円）・
  `supplier_data`（t-CO2e）は公式係数が無く、手動入力の選択肢からも外してある
  （車両は燃料 L として入力する。距離ベースの推計は燃料との二重計上の入口になるため）。
  既存レコードがあれば履歴に表示されるが、カスタム係数が無ければ `FACTOR_NOT_FOUND` として
  **未算定のまま残る**（デモシードでも水道 1 件が未解決として残る）。

## 4. Scope 2 の方式の扱い

- **マーケット基準／ロケーション基準（market-based / location-based）の区別は実装されていない。**
  該当する語・フラグ・二重計上の集計経路はコードベースに存在せず、
  ダッシュボードの `scope2Total` は**単一の値**である。
- 実装されているのは温対法（SHK 制度）の **基礎排出係数 / 調整後排出係数** の区分で、
  手動入力で「計算方法 → 供給事業者 → メニュー」を明示選択できる。
  自動解決で同一優先度に複数該当した場合は `adjusted`（調整後）を優先する（タイブレーク）。
- 事業者別係数は自動解決の候補から外してある（明示選択専用）。事業者を選ばなかった場合は
  **全国の代替値**（電気 0.000416 t-CO2/kWh 等）で算定される。
- 「メニュー(残差)」行は公表資料どおり収録しているが、**残差ミックスとしての方式区別には使っていない**。
  証書・クレジットによる調整を入力する機能も無い。

> GHG プロトコルの Scope 2 ガイダンスが求める二方式併記が必要な用途では、
> 現状の出力はそのままでは使えない。

## 5. Scope 3 の対応範囲

15カテゴリそれぞれについて、組織×年度単位で方式を**排他選択**する（`scope3_category_methods`）。

| 方式 | 採用値 | 備考 |
|---|---|---|
| `direct`（既定） | `scope3_category_emissions` に登録した t-CO2e | 外部で算定済みの値を持ち込む |
| `calculated` | そのカテゴリの `emission_results`（`scope='scope3'`）の合計＝IDEA 積上げ（`energyType='scope3_activity'`）＋ 標準係数で算定した廃棄物・出張・通勤 | IDEA 積上げは Ver.4.0 Excel の取込が前提 |

- 方式が排他のため二重計上は構造的に起きないが、**どちらの方式でも、値の妥当性は入力側の責任**である。
- **IDEA データは同梱していない。** 利用者が AIST から入手した Excel（GWP 列を持つ IPCC 版）を
  取り込む必要がある。取込は数十MBのアップロードを伴い、リクエストボディ制限のあるホスティング
  （Vercel の 4.5MB 等）では動作しない（`docs/setup-guide.md` 2-F）。
- 同梱の Scope 3 代表原単位 42 件（廃棄物12・出張12・通勤10・輸送8）のうち、**廃棄物と出張・通勤は
  手動入力の「標準」係数として自動算定に使われる**（係数の `scope = 'scope3'` から `categoryId` 5 / 6 / 7 を
  補って `emission_results` に保存する）。出張・通勤の活動量の単位は
  公式係数に合わせて **人・日**（km ではない）。出張は係数の選択に応じて 円 / 泊 / 人・年 でも入力できる。
- ただし **この算定結果がダッシュボードの Scope 3 合計に載るのは、そのカテゴリの方式が `calculated` の
  ときだけ**である。方式の既定は `direct` のため、標準係数で入力しただけでは Scope 3 合計は増えない
  （直接入力値 0 が採用される）。データ入力フォームは方式が `direct` のカテゴリを選ぶと注記と
  Scope分析画面への導線を出す。方式の自動切替は行わない（直接入力値との二重管理を避けるため）。
  方式はカテゴリ×会計年度ごとに持つため、注記の判定・文面はどちらも**対象年月が属する会計年度**
  （画面上部で選択中の年度ではない）で、導線は年度を URL（`/scope-analysis?fy=<会計年度ID>`）で運ぶ。
  選択年度はタブ内の状態で永続化されないため、新しいタブで開いても文言どおりの年度で開けるようにしている。
- **輸送 8 件は使われない。** `freight_transport` / `logistics` を手動入力から登録する手段が無い
  （IDEA 原単位の積上げか直接入力で持ち込む）。
- **水道（`water`）は上水道の購入としてカテゴリ1 に載せる。** 公式係数は同梱しておらず手動入力の
  選択肢にも無いため、算定には自社設定のカスタム係数（適用範囲は種別から `Scope 3` に決まる）と
  取込済みの活動量レコードが要る。カテゴリ1 の方式が `calculated` のときだけ Scope 3 合計に載る。
- カテゴリの網羅性は担保していない。15カテゴリの「枠」はあるが、
  各カテゴリを埋めるためのデータ収集・算定方法の選択は利用者側の作業である。
- サプライヤー別排出（`supplier_emissions`）は表示専用で、Scope 3 合計には算入しない。

## 6. 排出係数マスタの収録年度と解決規則

- 同梱の公式係数は **`applicableYear` = 2025年度のみ**（`scripts/official-factors/generate.ts` の `YEARS = [2025]`）。
  未公表年度の行は作らない（翌年度へ同じ値をコピー登録しない）。
- 対象年度の係数が未公表の間は、**直近1年前まで**の公式係数を「暫定適用」し、
  入力フォームの係数詳細に「〈年度〉年度の係数を暫定適用」と理由を表示する
  （`calculation-logic.md`「未公表年度の暫定適用」）。1年より古い係数は使わず、未算定として残す。
  新年度の係数を登録すると、そのあとに算定するレコードは正式係数で計算される。
  **暫定適用で算定済みのレコードは自動では切り替わらず**、データ入力画面の
  「正式係数で再算定」から明示的に差し戻す必要がある（`functional-spec.md` §4.2.3）。
- カスタム係数は年度完全一致のみで、暫定適用しない。
- 年度更新は利用者側の運用作業（`scripts/official-factors/README.md` の手順）。
  **自動で最新係数に追随する仕組みは無い。**
- 地域一致の標準係数（優先度4）は、拠点の地域（北海道・東北・関東・中部・関西・中国・四国・九州・海外）の
  ラベルと係数の `regionName` の文字列完全一致でのみ判定する。同梱の公式係数はすべて `regionName = '全国'`
  なので、**同梱データだけでは優先度4は発生しない**。「東京電力管内」のような事業者エリア名との対応表も
  未整備。
- サプライヤー固有係数（優先度2）は、活動量にサプライヤー紐付けが無いため**決してヒットしない**。

## 7. 検証されている範囲

| 対象 | 検証手段 |
|---|---|
| 算定コア（係数解決・単位換算・丸め・暫定適用・IDEA 積上げ） | ユニットテスト（vitest、`npm run test`） |
| 画面の主要導線（手動入力→算定→ダッシュボード反映→CSV出力） | E2E スモーク 3 本（Playwright、`npm run test:e2e`。`docs/e2e-testing.md`） |
| 係数シードの件数・代表値 | 生成スクリプトの assert とスポットチェック（`scripts/official-factors/generate.ts`） |
| 算定結果の期待値 | デモシード末尾のメモ（scope1=1.145 / scope2=0.924 / scope3=12.500、水道1件が未解決） |

**上記以外は検証されていない。** 具体的には:

- 制度・基準への適合性の確認は行っていない（温対法報告、SSBJ / ISSB 開示、GHG プロトコル、CDP 等）。
- **第三者保証・第三者検証は受けていない。**
- 公表係数の転記内容について、公表元との第三者照合は行っていない
  （`gas.tsv` / `heat.tsv` / `fuels.tsv` / `scope3.tsv` は手書き転記、`denki.txt` は PDF 抽出のパース）。
- 制度の提出様式での出力は無い。レポートは以下の3種類（CSV / 印刷用 PDF ビュー）で、
  いずれも**社内での確認・共有を想定した独自様式**である。

  | レポート種別 | 内容 |
  |---|---|
  | 年度温室効果ガス排出サマリ | 年度別 Scope1/2/3 合計と構成比、拠点別 Scope1・2 |
  | Scope 3 カテゴリ別詳細分析 | カテゴリ別内訳・算定方式・IDEA 引用表記 |
  | 拠点別排出量・エネルギー内訳 | 拠点別 Scope1/2・エネルギー種別使用量 |

  全種別に「データ充足状況」（算定済み／未算定の件数と充足率）を載せる。未算定レコードは集計値に
  含まれないため、「集計できた分の合計」を全体の排出量と誤認しないためのもので、
  **充足率は件数ベースであり、システムに未入力のデータは検知できない。**
  算定方法が直接入力のカテゴリに属する Scope 3 の活動量は、算定済みでもカテゴリの採用値に
  入らないため充足率の分母・分子から外し、除外件数を注記に出す。

## 8. 数値の丸め

- `emission_results.emissions` は小数第6位（1g 粒度 = 10^-6 t）で保持する。
- 画面・レポートの表示は小数第3位（1kg 粒度）。
- 集計値（`dashboard_aggregates` の scope1/2/3Total、`scope3_category_emissions.emissions`）は
  `numeric(15,3)` で意図的に据え置いている。
